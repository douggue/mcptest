# Engine patches

Applied in filename order by `scripts/fetch-engine.sh` on top of NewBlackbox commit
`89b59836c66f173756a4ae258cf379a957649820`. One fix per file. Each is a plain `git diff`, so
`git apply` works on it. Details and evidence for each fix: `docs/research.md` section 3.

| # | Patch | What it fixes |
|---|---|---|
| 0001 | remove-log-upload | Deletes `LogSender` (POSTed logcat to a Vercel relay), makes `getLogSenderChatId()` return null, turns `sendLogs` into a no-op |
| 0002 | disable-public-logcat-dump | `startLogcat()` wrote the whole device logcat to public `Downloads/logs` on every start |
| 0003 | hiddenapibypass-replaces-freereflection | Drops the JitPack dependency; uses LSPosed AndroidHiddenApiBypass (Apache-2.0, Maven Central) |
| 0004 | fileutils-no-shell-strings | `chmod` / `ln -s` fallbacks built shell strings from paths; now argument arrays |
| 0005 | async-engine-startup | Adds `BlackBoxCore.doCreateAsync(ReadyCallback)` and `isCoreReady()` so the UI process never blocks on startup |
| 0006 | grant-network-perms-stop-sms-autogrant | Grants the six network permissions to clone packages (fixes WebView `ERR_CACHE_MISS`, upstream #68); stops reporting `SEND_SMS` as granted |
| 0007 | identity-store-and-hooks | New `IdentityStore`; Android ID (settings provider), IMEI/MEID/IMSI and Wi-Fi hooks now serve per-clone values instead of `md5(hostPackage)` and a fixed `BlackBox_Wifi` |
| 0008 | native-per-clone-spoof-and-maps-filter | Replaces the hard-coded global Pixel 6 / Android 12 property table with a per-process table; adds a `/proc/<pid>/maps` filter |
| 0009 | raise-sdk-levels | Engine root build: compileSdk 36, targetSdk 36, minSdk 24, NDK variable |
| 0010 | native-per-clone-proxy | In-process SOCKS5 / HTTP CONNECT proxy, proxied DNS, UDP block (functionally tested on a Linux host) |
| 0011 | per-clone-notification-label | `NotificationLabel` adds a per-clone sub text to every notification the clone posts |
| 0012 | async-startup-report-real-failure | `doCreateAsync` reports failure honestly and allows a retry |
| 0013 | proxy-dual-stack-and-webview-internet-permission | Proxy hook: v4-mapped (`::ffff:198.18.x.x`) targets from Java's dual-stack sockets are resolved to the fake-DNS hostname, and an IPv4 proxy is reached from AF_INET6 sockets via a v4-mapped address (was `ConnectException`). Adds `checkPermissionForDevice` (Android 15+) so WebView sees INTERNET as granted (was `ERR_CACHE_MISS`) |
| 0014 | stability-fixes-and-faster-proxy-handshake | Service connections are forwarded as raw transactions, so they work whatever parameter list `IServiceConnection.connected` has on the running Android (upstream #60). Takes upstream PRs #72, #73, #74, #75, #78, #79, #80, #81 (SecurityException and null-unboxing crashes, dead clone processes and stale tasks, AppOps return types, PendingIntent results) and the duplicate-launch guard and 10 s launch timeout from #77. SOCKS5 handshake in one round trip instead of three, with automatic fallback for proxies that need step-by-step |
| 0015 | android17-package-list-type-and-small-packageinfo | List results are built in the type the hooked method really returns (Android 17: `getInstalledPackages` returns `PackageInfoList`; returning `ParceledListSlice` crashed Facebook with ClassCastException). All components of a `PackageInfo` share one `ApplicationInfo` object, so the parcel is squashed like the system's (Facebook's was 6 MB and failed the 1 MB binder limit) |
| 0016 | sim-properties-per-slot-and-quiet-property-hook | Spoofed `gsm.*` properties take the per-slot shape of the real value, so the SIM operator, country and name are no longer empty when the active SIM is not in slot 0. The property hook reads names inside the real callback instead of the deprecated `__system_property_read`, which truncated long names and logged an error on every framework cache check |
| 0017 | retry-with-host-package-on-securityexception | Calls with no specific hook that fail with SecurityException because the clone's package name does not belong to the host uid are repeated once with the host package (YouTube: `IMediaRouterService.getSystemRoutes`; Google Play services: `IDevicePolicyManager.getAccountTypesWithManagementDisabledAsUser`) |
| 0018 | locale-manager-and-null-service-intent | `ILocaleManager` proxy (from upstream PR #62, corrected to proxy the interface): `setApplicationLocales` is acknowledged and dropped instead of failing with SecurityException (YouTube). Service restarts with a null intent no longer crash the clone (Google Play services) |
| 0019 | credential-manager-main-user-and-denied-calls | `ICredentialManager` proxy answers every request with "no credential" (Facebook's login screen died on `executeGetCredential`). `IUserManager.isMainUser` returns true when the real call is denied (Google Play services). Unhooked calls that return void or boolean and are denied for a missing permission log and return instead of throwing |
| 0020 | bind-service-instance-name | `bindServiceInstance` drops the instance name before binding the proxy service (Facebook's embedded Chromium: "Can't use instance name '0' with non-isolated ... service"); a bind the system rejects returns 0 instead of throwing an undeclared exception |
| 0021 | proxy-dns-table-shared-and-persistent | The fake-DNS table (fake address ↔ hostname) is kept in a per-clone file, shared by all processes of the clone under a file lock and kept across restarts. Before, each process had its own in-memory table, so a fake address an app had cached or passed to another of its processes meant a different host there and the proxy connected to the wrong site (TLS certificate errors with a proxy on). Lookup results are allocated in one block like bionic's (no leak per lookup) |
| 0022 | proxy-relay-for-nonblocking-sockets | A `connect()` on a non-blocking socket no longer does the proxy handshake on the caller's thread. It is connected to a relay thread on loopback and returns at once; the relay connects to the proxy, does the handshake and copies the bytes. Before, an app with one network thread (TikTok and everything else built on Cronet, media players) was stopped for a full proxy round trip on every new connection, so nothing moved on its other connections meanwhile: pictures loaded, videos stalled. Measured with `native-tests/` on an emulator, proxy needing 1 s per connection: 20 connections opened by one thread were usable after 1.4 s instead of 20 s, and a stream on the same thread paused for under 0.2 s instead of 1 s on every connection. Blocking sockets keep the in-place handshake. A proxy that drops pipelined bytes is detected and the same connection is retried step by step instead of being lost |
| 0023 | proxy-relay-log-and-abandoned-connects | The relay writes one log line every 10 s it was busy: connections asked for, ready, failed (with the proxy's own answer or the reason), given up by the app, how long the proxy took, and KB/s down and up. Before, a proxy that refused, timed out or was slow left no trace, because the app only sees "connection reset"; the app's report now includes these lines. A connection the app closes while the proxy is still being reached is dropped at once instead of being carried through (a feed opens and drops connections all the time; with `native-tests/`, 40 of 40 abandoned connections still reached the proxy before, none after). A tunnel whose app side has ended is dropped after 15 s of silence instead of 120 s; a proxy that stops acknowledging data is given up after 30 s; the relay thread blocks only ordinary signals |
| 0024 | proxy-real-dns-peer-address-and-tunnel-log | **Names are looked up for real, through the proxy** (DNS over TCP to 1.1.1.1 / 8.8.8.8 inside a proxy tunnel, cached by TTL), so the clone gets the true addresses as seen from the proxy's exit. Before, every name got its own fake address, which hid from the app which names share servers; a browser-style stack reuses one connection for all names on a server it is already connected to, and could not. On a phone, TikTok opened 61 connections in 10 s through a fast proxy and dropped each within seconds. Measured through that proxy: 32 TikTok names sit on 13 server groups, 20 of them sharing an exact address with another. A proxy that refuses port 53 gets the old behaviour (placeholder address, name sent to the proxy). **`getpeername()` returns the address the app connected to**, not the relay's or the proxy's. **The relay log says who ended each tunnel** (app or proxy side, cleanly or abruptly), how long tunnels lived, how much they carried, when they ended and where new connections went |
| 0025 | proxy-tls-outline-sni-destination-and-dns-fallback | From a phone report with 0024: TikTok opened 85 to 140 connections per 10 s, nearly all to three servers (two video hosts and the main API), each closed by the app itself within 2 s after under 1 KB sent and under 8 KB received; TikTok's video servers were verified to serve that proxy fine. **The relay now records the outline of the TLS conversation** on tunnels that end young (record types and sizes per side, never content), so a report shows whether the app rejected the server's answer or finished the handshake and was refused. **The server named in the app's TLS hello is used as the destination** when it differs from the name a placeholder address stood for (an app may keep such an address and reuse it for another server; asking the proxy for the table's name then reaches a server whose certificate the app rejects). **One failed lookup no longer switches DNS-through-the-proxy off**: a name the resolver cannot answer gets a placeholder on its own, and only a refusal or three failures in a row pause lookups; each failure is logged with its reason. Logs which hooks installed |
| 0026 | proxy-lookup-honours-numerichost | **The cause of "pictures load, videos do not" with any proxy.** The lookup hook answered every name with an address even when the caller passed `AI_NUMERICHOST`, which asks "is this text an address?" and must fail for a name. Android implements `InetAddress.isNumeric()` with exactly that call, and its TLS library (Conscrypt) leaves the server name (SNI) out of the handshake when the host "is an address". So with a proxy on, every Java TLS connection in a clone went out without a server name; the server replied with its default certificate, the app rejected it and retried without end. Proven with the TLS outline from patch 0025: a phone logged Certificate messages of 2396 B (TikTok API and one video host), 4821 B (another video host) and a server `handshake_failure` (a third); the same servers return exactly those when asked without a server name, and the correct certificate (2033, 2051, 3733, 2809 B) with one. Connections made by the app's native stack carry the name and were never affected, which is why sign-in and the feed worked. The hook now leaves `AI_NUMERICHOST` lookups to libc |
| 0027 | bind-instance-name-only-dropped-for-proxy-service | Patch 0020 (and the engine's own `bindIsolatedService` hook) dropped the instance name of every named bind. That is right when the target is replaced by the engine's proxy service, and wrong when the bind goes on to a real service in another package: WebView starts each renderer process as a named instance of one service in the WebView package, so with the name gone every renderer of every clone asked for the same instance, only the first got it, and Chromium retried the rest without end (a phone logged `ChildProcessConnection.start failed, trying again` about 350 times a second). The name is now dropped only where the proxy service becomes the target. Not compiled or run locally (no JDK); not verified on a phone |

To add a fix: edit `engine/`, then `git -C engine diff > patches/00NN-name.patch`, commit the patch file, and
re-run `scripts/fetch-engine.sh` to prove the whole series still applies from scratch.
